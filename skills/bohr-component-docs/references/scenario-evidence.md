# Web／桌面端场景证据与规则对齐

## 采集记录
| 字段 | 内容 |
| --- | --- |
| 场景编号 | 当前任务内稳定编号 |
| 产品／端侧 | Web、桌面端或未确认；版本、环境、操作系统按可取得信息记录 |
| 页面入口／对象 | 页面位置、入口路径、业务对象 |
| 用户任务 | 用户想完成什么 |
| 条件／阶段 | 前置条件、任务阶段、空间条件、权限条件 |
| 组件关系 | 目标组件与标签、容器、其他操作的关系 |
| 状态与行为 | 默认、悬停、聚焦、加载、错误等；区分观察与推断 |
| 证据 | 链接、节点、截图或操作记录、采集日期 |
| 覆盖边界 | 哪些状态未检查、另一端是否检查、仅静态还是实际操作 |

只收集该任务需要的界面，截图及示例避免暴露个人信息、密钥、私人文件内容。对线上操作保持任务范围，不通过付费、删除或发送内容来验证普通示例。

## 对齐方法
1. 先按操作目的归组，如提交任务、确认操作、选择内容、切换视图。
2. 再比较共用语义与端侧差异：同目的不要求同布局；系统能力、导航、窗口空间等可能合理不同。
3. 最后补适用条件：任务阶段、内容密度、异常状态与操作数量。
4. 区分四种对照结果：
   - 两端一致：证据覆盖的相同条件下表现一致。
   - 合理差异：有明确规范、能力限制或产品决定支持；只有观察差异时不能直接称合理。
   - 待确认差异：表现不同但缺少选择依据。
   - 仅一端存在：在明确范围内确认另一端没有对应入口；未查到不足以证明不存在。
5. 形成“条件 → 选择 → 原因 → 例外”的规则，并关联来源。

## 案例选择与说明
每条关键规则先选一个代表案例；差异明显时再补另一端或边界案例。不要求每条规则都有重复的两端截图。例子应同时对齐：
- 业务任务与适用条件。
- 实际组件属性和状态。
- 周围内容、主次操作与布局关系。
- 公共样式和规则。
- 说明中给出的选择理由。

案例来源标为“线上观察”“已有设计示例”或“本次示意”。没有业务素材时可以用组件搭建示意，写清尚未在线上核验，不虚构页面或上线状态。


业务使用规则正文须给出适用条件、选择理由、关联组件边界和例外；节点编号、字体故障与维护日志留在验收记录。用户要求玻尔经典案例时，必须定位真实产品入口并记录端侧与日期；Form Examples 等原库样例不能充当实机证据。要求可复用案例时，Figma 中必须插入有主组件链的真实实例，截图只能作为观察证据。
