# 统一验收门槛

采用已通过 / 未通过 / 未验证 / 不适用四种状态；不适用必须给理由。验收对象是实际产物及其模板，不是脚本日志或 Skill 中出现了哪些词。

## P. 原稿保护与红线门禁
- 提供英文保护范围、中文写入范围和共享依赖基线；写入后英文内容、结构、引用、样式及变量解析值无非预期变化。只核对文字不算通过。
- 图标来源、语义、绘制颜色、尺寸与父层覆盖、Light/Dark 和隐藏状态逐项核实；保护检查或任一适用红线缺证据都不得整体放行。
- 未通过、未验证必须列出受影响范围和恢复条件；不得用其他通过项抵消。

## A. 内容一致性
- 中文组件身份标题及规则/示例文档标题同时保留正确的英文标识与中文名；page、文档 Frame name 与可见标题按 [命名规则](figma-naming.md)逐项读回。纯中文身份标题、错误组件族或模板残留名称均未通过。属性键值、主组件技术路径和引用链不得因双语化改变。
- 内容字段到模板位置的映射齐全，可见分区和表达形式与参考一致；不把信息清单变成新的展示板或大表格。
- 属性键、类型、可选值、默认值及来源与实读相符；样例和建议未伪装为能力。
- 原英文、技术标识、版权、链接和用户改动保留；翻译覆盖实际范围，无英文时标新增整理。
- 正常与边界案例有据；缺失项明确，不制造假状态。规则四类依据可区分，冲突有来源。

## B. 形式一致性
- 存在已确认的模板锁定记录；各组件使用同一适用版本。候选不能通过正式模板门槛。
- 逐项比对页面/内容宽度、边距、间距、布局层级、文字角色、字体字重、字号行高、颜色/变量、边框、圆角、主题与预览容器。
- 逐角色匹配页标题、类别标签、简介、章节、案例、注释、正文与页脚，包含字重及有效透明度；不同组件本体的合法差异不判为模板失败。
- Header 实例/层级、Preview 包装、内容边界线及 Footer 对齐轴均有源/目标节点证据，不能遗漏低对比装饰结构。规则页和示例页分开比较。
- 无自定新字体、新版式、展示板数量或替代预览；披露偏差不等于形式通过。

## C. 实例与可维护性
- 预览为真实 INSTANCE，mainComponent 与预期一致，嵌套实例及必要变量绑定保留。
- 预览与说明按模板组织；移动文档不需另外手选浮动实例。
- 在测试副本将案例说明增加到原长度约 2–3 倍，验证自动换行、预览及后续内容重排，无覆盖或裁切；不改正式业务内容来测试。
- 模板声明支持的多宽度/主题按范围检查；未声明不外推。重复执行只更新已有节点，不产生重复文档，不覆盖用户新增段落。

## D. 来源与场景
- 业务案例逐场景检查“来源 → 必要元素目标 → 业务关系 → 完整片段根”；结合原始观察复核清单无遗漏。缺必要输入或相关操作时，单体INSTANCE及变量检查通过也不能通过场景验收。记录须符合task-evidence.md的business_scenarios结构，并通过记录校验；记录校验不能替代实际场景判断。
- Web、桌面端各有证据、操作范围和日期，或明确未验证；无证据不写“两端一致”或“仅一端存在”。
- 已有设计、线上观察和本次示意区分；截图不证明提交、上传、键盘或状态转换行为。
- 无线上访问不是改版式的理由。可交付已通过的设计文档部分，不能称跨端业务验证完成。

## C1. 图标来源
- 100% 图标节点已盘点，范围包括示例、业务组件源实例及所有嵌套子树；不能只检查最外层实例。
- 每个图标均为批准 Bohrium 库的可追溯 `INSTANCE`，有 `libraryKey`、最终 `componentKey`、`mainComponent.remote`、组件名称和实例链路证据。
- **绑定位置红线**：业务组件中的线性功能图标必须是 `Bohr icon/Wrapper` 实例，并通过其 `Bohr icon#...` INSTANCE_SWAP 属性指向具体库图标；直接 `Icon/...`、`folder`、`HugeIcon` 或 `IconPlaceholder → HugeIcon` 均失败。
- 脱离批准库实例链的独立 `VECTOR`、`BOOLEAN_OPERATION`、其他形状、SVG、图片、emoji、Material/HugeIcon 或无法解析的本地包装层均为未通过；名称相同或外观相似不能豁免。
- 搜索不到精确库图标时标记阻断并在本次中文／业务组件内处理，不得影响英文原稿，不能在文档页用自绘图标或截图替代。
- **颜色红线**：每个实际绘制的可编辑图标 Paint 的 fills/strokes 变量绑定必须存在并指向批准的组件库图标颜色变量；硬编码 RGB/HEX、未绑定 Paint、隐藏色值覆盖或错误主题/状态模式均失败。图标来源通过但颜色变量失败，整体仍不得放行。

批准的文件类型多色资产按专用组件族验收，不强制套线性 Wrapper，也不得改成单色；源库未绑定颜色单列缺口。空 fills 不要求伪造绑定，实际 strokes 仍必须检查。

## C2. 图标引入后的实际表现（强制）
- 执行 [引入后强制检查](icon-provenance.md#引入后强制检查)，每个适用图标的描边、内部几何、颜色语义、主题继承及状态覆盖都有源/目标证据。
- 描边的变量解析值和最终实际值分别记录；与批准尺寸策略一致、无重复缩放；外框正确不能代替内部几何检查。
- 颜色语义不被静默改绑；实际模式与语义容器一致，无未经批准的实例锁定主题或 opacity 覆盖。
- 隐藏及非默认变体在同口径清单中；局部截图、数值回读和引用链共同验收。失败或未验证阻断本次引入完成。

## E. 视觉检查
- 参考与目标使用相同倍率比较 Header、章节/案例标题、注释、预览、底部和页脚。整页缩略图只检查全局，不能替代正常比例细节。无裁切、错位、错误换行、空预览或不可读文字。
- 结构与截图缺一不可：截图对齐不证明布局关系正确；节点类型正确不证明画面可用。
- 仅复查相关修改影响的区域，保留最终截图、节点清单与模板对照结果。

## 完成判定

先按 [任务清单与证据记录](task-evidence.md) 运行 `scripts/check_evidence.py`，保留输出。校验失败、没有运行或记录不完整时不能宣称本次完整通过；可报告已验证的部分与剩余项。该工具只核对记录、文件摘要与声明的差异，不证明证据真实、源清单穷尽、视觉正确或线上访问成功，仍须完成本文件全部适用验收。禁止把“记录校验通过”写成“组件验收通过”。

先按本次请求确定适用项，再逐项读取 [执行检查记录](execution-checks.md#修改后立即读回)。每项必须有目标/状态、预期、操作后实际结果及证据位置；缺任何决定性证据记“未验证”。已观察到偏差记“未通过”；工具阻断另记原因，不能当作“不适用”。历史样本、推演或局部机制通过不能填入本次完整产物的通过项。

**整体状态取全部适用项，不取成功动作的数量。** 下表中的 B/C 等代表所需检查全部通过；C1/C2 在涉及图标时同样适用。任何适用必检项未通过或未验证，只能按已完成范围报告部分完成；D 的线上缺口按表中单独边界处理。修复后只更新已重新验证的项，不自动将其他缺口一并关闭。

| 状态 | 可用表述 |
| --- | --- |
| P/A/B/C/E 的所有适用检查通过，其余附不适用理由；D 在约定范围已验证或合理不适用 | 按规范完成本次范围；局部任务只称该项完成，不等于整份文档或发布 |
| P/A/B/C/E 的所有适用检查通过，D 有明确线上缺口 | 设计文档部分完成，端侧验证未完成 |
| B 或 C 未通过，如缺字体或浮动实例拼贴 | 内容草稿/部分完成；不得称按规范完成 |
| 只有包校验、文字审查或截图之一通过 | 只报告具体检查，不升级为技能效果验证 |

图标来源、颜色变量或 C2 引入实际表现未通过/未验证时，即使内容、布局和截图通过，也只能报告“部分完成/图标红线阻断”，不能称按规范整理完成。

最终简述：链接、模板版本、内容/形式/场景状态、阻断与恢复条件。详细日志放本地，不生成非标准展示板。逐角色比对未完成时，只报告已检查范围，不能称“已对齐”。

## 整页区域与导航

整页整理或补齐组件文档时，按 [整页区域与导航验收](page-completeness.md) 逐项检查；局部修改只复查受影响项目：

- 基础元素、组合/业务组件、任务进度按已确认职责分区，不能混排。
- 矩阵行列标签、完整外轮廓、单元格间距与对齐匹配指定参照；真实变体无遗漏，Boolean 对照覆盖实际可见差异。
- 元素说明对应实际属性类型、默认值及编辑入口；导航指向当前组件或文档。
- Light / Dark 案例数量、主组件与属性一致；记录模式绑定和关键颜色解析值，排除内部固定白底和阻断主题继承的覆盖。

只完成规则与示例正文不等于整页完成；静态包校验、Figma实例验收和Web/桌面运行验证分别报告。
