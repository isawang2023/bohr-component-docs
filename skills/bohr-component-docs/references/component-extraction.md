# 组件抽取与状态验收

用户要求把已有设计搭成可复用组件时使用；与 figma-use、figma-generate-library 一起执行。抽取不是自动推断业务，也不是组件文档排版。

## 写入前锁定

先向用户明确本次组件清单：完整路径、源节点、职责、基础依赖、目标 page ID、属性维度与不包含的业务能力。以实际源稿和批准库为依据，先原子、后组合、最后场景实例。已授权任务直接执行；新增业务决策才需要澄清。

页面与组件路径分别检查：每次写入显式设置目标 page，创建后沿父链核对；路径唯一不等于 page 正确。修改前读取用户最新改动，按已知节点 ID 更新，避免另建同名版本。

## 状态不是一个开关

- 交互 State（Default/Hover/Focus/Disabled）、业务 Status（Running/Completed/Failed/Cancelled）、展开 Expanded、内容有无与内容文本分别建模；只有真实可视或行为差异才建立变体。
- 先列合法组合及不变量，例如 Disabled 不展示已展开入口；Completed 的已完成数应等于总数；失败/取消不自动变成完成；空输入的发送状态不能仅靠删除附件得出。
- 灰色不证明禁用。读取组件属性、变量和原型。未支持的暂停、重试、切换策略不自行添加。计数口径未确认时说明是工作稿约定。
- 可重复条目复用子组件；样例条目数不是业务上限。交互图只说明 Figma 原型，不证明产品已有对应能力。

## 引用、覆盖与属性

- 继承库组件和 Token，记录 mainComponent/key、Wrapper/INSTANCE_SWAP、fills 与 strokes 的绑定。尺寸同时查外层槽位、内部图形边界及缩放，不通过重绘图标修复位置。
- 业务文本与嵌套图标文字分开处理，禁止 findFirst(TEXT) 或无差别递归改色。PDF 等资产内部文本不是文件名，不得绑定业务 text/default。
- 先比较源组件与实例覆盖，再清除确认为错误的局部覆盖。resetOverrides 可能同时清除尺寸和正确内容，不能整树盲目重置；修改后复核 geometry、内容及变量。
- 线性功能图标按图标规范使用 Wrapper。文件类型图标等批准的专用资产按其正式组件族引用，保留多色语义，不强行套单色 Wrapper。源资产中未绑定颜色单列为源库缺口；引用正确不能被写成全部 Token 验收通过。
- 已有嵌套组件优先暴露原生属性；工具不支持属性转接时使用可验证的 exposed instance 机制，不 detach、不伪造可编辑属性。调用前查 API；两个相同类别错误后查接口，不继续猜键名。失败后按工具是否已提交决定读取或重试。

## 必须验收实际实例

1. 结构：路径唯一、目标 page、变体组合唯一、默认变体、主组件链路和必要嵌套属性。
2. 绑定：分别检查颜色、字号、行高、间距、圆角；图标检查 fills 和 strokes。不能以等值 HEX 或外观相同代替绑定。
3. 默认实例：为每个业务状态创建真实实例，读取文本、计数、图标和属性。共享 TEXT 属性默认值可能覆盖某变体的主组件文案，必须捕获如 Completed 却显示 2/5 的错误。必要时拆分状态专属内容属性，并说明其用途。
4. 编辑：实际改变标签/任务名/计数，复核实例值；长文字至少检查换行、容器高度和数字/操作不重叠。状态切换后检查内容覆盖是否保留合理。
5. 视觉：同倍率核对主要状态；在一个紧凑预览区放真实实例，主组件另放构建区。保留可复查证据，移除测试节点。

字体不可加载时保留原稿；先推进不受影响工作，未经授权不替换。用户允许替代时限定工作稿范围，记录替代字体和恢复项，不称为原字体通过。

## 缺口与完成表述

分别记录 Skill 缺失、规则未执行、工具限制、源库缺陷、未确认业务。每条修复附前后证据和影响范围。仅改规则文本不等于真实行为通过；仅修复画布也不等于 Skill 已升级。工作区与已安装 Skill 分别窄范围更新并校验，保留既有差异，不自动发布 Git 或库。
