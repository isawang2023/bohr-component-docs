# 图标 Scale 生成与验收

适用于用户确认的 Bohrium 24px Wrapper 缩放路径；每次重新读取源组件与变量，历史 ID 仅作定位依据。正式源只读，测试在授权隔离页执行。

## 生成顺序

1. 取得批准的 24px Wrapper 主组件，确认外框 24×24、描边模式为 24px，记录源路径描边与几何。
2. `createInstance()` 后加入目标容器，通过已查得的 `Bohr icon` INSTANCE_SWAP 属性引用批准图标。先 swap，再 Scale。
3. 使用 `instance.rescale(targetSize / instance.width)` 整体缩放；保留 Size=24 与 24px 描边模式。禁止切换小尺寸变体后再 Scale、仅 resize 外框、硬编码补描边。
4. 颜色按目标语义和主题继承，按 [颜色保真与修复](icon-color-workflow.md) 检查绑定、别名、显式模式、有效透明度及最终颜色；尺寸变化不授权改变颜色。
5. 预期描边＝批准源描边×累计 Scale 比例。分别比较内部路径位置、宽高、描边、端点连接、Paint 及有效透明度。变量解析基值不必等于最终描边。
6. 重复 swap 和目标尺寸操作后重新读取，几何、描边、颜色与实例链必须稳定。已有实例的来源、累计缩放或用户覆盖不明时，不把创建流程当作无条件迁移脚本，不 detach 或重置整树。

## 判定与证据

### 既有嵌套实例的受限迁移

新建流程与存量修复分开。遇到 `rescale: This property cannot be overridden in an instance: size` 时保留错误证据，按工具的提交/回滚状态处理，不重复强行调用、不 detach、不重建父组件。切换 Size=24 可能使外框膨胀，不能假设会保留目标尺寸。

只有同时满足以下条件，才可在授权目标中保留现有尺寸变体、仅修正描边变量的基值模式：原图标来源可追溯；内部路径几何已按批准源正确等比缩放；绑定与模式证据能确认多余的尺寸模式缩减；恢复源基值模式后实际描边等于源描边乘既有比例，且位置、尺寸、显隐、透明度和实例链均不变。该路径是受控存量迁移，不替代新建的24px Wrapper → Scale流程，也不授权把全库变量一律设24px模式。

修复后覆盖全部受影响尺寸、主题和隐藏实例，并重复同图标swap。源字段保护、文字及布局差异分别记录。切换尺寸变体、换不同图标或用户覆盖变化属于新操作，必须重新验证；同图标swap通过不能推定这些操作也通过。任一条件缺证据则阻断该路径，不能以临时改线宽补偿。

本次Bohrium隔离InputGroup已有8/12/16px实例的受控修复是上述路径的实测依据；不把该例推定为所有Figma库的通用行为。

检查器将基值、比例、预期值、实际值分列。mail 的 1.8×16/24＝1.2 与 1.8×12/24＝0.9 是本次基准；在该 mail 基准下实际 0.8/0.45 阻断，保留基值1.8但实际1.2/0.9则通过描边项。其他图标必须读取各自批准源值，不能直接套此数值。颜色单独判定，不能被描边通过抵消。

真实测试必须从主组件新建后 swap、rescale，不能只克隆正确样本冒充生成通过。覆盖24/16/12、Light/Dark、重复swap、隐藏实例进入遍历。保存首次、恢复后结果、截图与源节点保护快照。正常路径、负例检测、真实修复分别计数。
