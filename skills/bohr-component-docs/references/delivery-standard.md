# 组件内容与版式交付约定

## 三项内容与版式约定

适用于完整组件整理；纯翻译、局部修复或用户明确暂缓/限定端侧的任务按其范围执行，不借此扩大任务。完整整理默认包含以下三项，不等用户再次逐项提醒：

| 部分 | 应交付的内容与对应关系 | 不能作为通过依据 |
| --- | --- | --- |
| 中文规则 | 英文原段落/节点 → 中文译文逐段对应，保留原意、条件、例外及技术标识；忠实翻译允许自然中文表达 | 擅自扩写、删减、归纳改成另一套规则；原文没有的内容标“新增整理”也不等于可混入译文 |
| 玻尔业务规则 | 主动查阅玻尔 Web 和桌面端真实入口，保存端侧、入口、日期、条件/操作及原始结果；观察 → 有依据的业务规则 → 完整可编辑案例可追溯，与原文翻译明确区分 | 英文库样例、通用经验、推测或自写说明冒充真实业务；只有静态画面就推断校验、权限、限额或提交行为 |
| Button 版式 | 锁定 [Button 两种参照](bohrium-button-template.md)，规则页与示例页分别映射；复用对应容器，核对页头/页脚结构与实例关系、字体/字重、颜色绑定、透明度、间距、边界线及对齐轴 | 手画近似页头页脚，只复制字号/页宽，或版式有差异却称已对齐 |

已有完整原始业务证据可在核对对象、范围、日期与有效性后复用，不为“主动”重复访问。缺证据时先找当前可用入口并实际尝试两端；未尝试是执行遗漏，不是外部阻塞。某端受阻保存失败与恢复条件，继续另一端和可执行部分；没有业务依据的新增断言移出正式规则，待确认建议留在本地记录，不能仅加“建议”标签后混入正式交付。无英文原文时如实标新增整理并逐项注明能力/业务依据，不虚构英文来源。

开工在现有 contract 锁定组件/节点、英文范围、Button参照、交付根和逐端取源任务；不新造平行台账。制作时将上述三份对应关系保存在本地执行记录。交付前结合已有证据集中列出差异，由执行端修正并只复验受影响项；未改动且证据仍有效的项不重验。不以列出缺口、校验器通过或调用追踪 Skill 代替修复，也不新增独立验收循环。真实受阻只交有界部分成果，不标整组件完成。
