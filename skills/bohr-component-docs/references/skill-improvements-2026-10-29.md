# bohr-component-docs Skill 改进方案 · 2026-10-29

> 基于 Composer 组件文档整理的实际执行，提出 SKILL.md 改进建议。
> 不修改现有 SKILL.md，仅作为参照方案。

## 改进 1：步骤 4 "按锁定模板写入"补充规则页约束

### 现状
SKILL.md 步骤 4 详述了模板复用、字体、预览容器等要求，但未明确**规则页的标题区也需使用 _Docs/Header 实例**。bohrium-button-template.md 虽然区分了两种版式，但主 SKILL.md 的流程步骤未强制引用。

### 建议在步骤 4 增加

```
规则页与示例页的标题区均须使用已确认的 Header 组件实例（如 _Docs/Header），不得手工重建。
手工重建即使字号一致，也可能遗漏字重、opacity、Token 绑定和链接结构。
```

---

## 改进 2：步骤 5 "验收与交付"增加图标子项

### 现状
SKILL.md 步骤 5 提到"返回结果链接、模板版本、完成范围与剩余缺口。分别报告内容、形式、场景验证、图标来源和图标颜色变量验证"，但未要求在画布的维护记录中**显式包含图标审计表**。

### 建议在步骤 5 增加

```
维护记录必须包含图标来源审计表，至少覆盖：
- 图标角色 / 目标节点 / 包装方式 / libraryKey / componentKey / 颜色变量 / 状态
- 区分文档区域（预览实例）和源组件内部的图标问题
- 源组件图标问题记录后标注"归属源组件，不阻断文档交付，需单独修复"
```

---

## 改进 3：组件集属性的记录格式

### 现状
document-template.md 中属性表模板面向常规属性（类型/可选值/默认值），但 Composer 这类业务组件的核心"属性"是 variant 轴 Property 1，不是常规 prop。规则页以叙述覆盖，未列属性表。

### 建议在 document-template.md 增加

```
### 组件集变体属性

| 组件集 | 变体轴 | 技术标识 | 可选值 | 默认值 | 中文含义 |
|---|---|---|---|---|---|
| Composer/Context | Property 1 | Property 1 | chat-引用 / chat-饮用+文件 / chat-文件+skill | chat-引用 | 上下文材料类型 |

单体组件（无暴露属性）在同一位置写明"根级未暴露可配置属性"，不留空。
```

---

## 改进 4：废弃变量标记

### 现状
Skill 未提及变量名中的废弃标记（如 `--tailwind-colors(废弃)/*`）。源组件使用了这些废弃变量。

### 建议在步骤 2 "填充统一内容"增加

```
变量绑定审计中标记废弃变量名。废弃变量不等于绑定违规，但应记录：
- 变量名 / 废弃标记 / 使用位置 / 当前解析值 / 替代变量（如有）
```

---

## 改进 5：散落实例与辅助区域的处理

### 现状
Composer 页面除了文档区域，还有大量辅助内容：全屏场景布局、技能面板、文件添加面板、散落的对话实例。Skill 未说明如何处理这些非文档区域。

### 建议在"范围与授权"增加

```
组件页可能包含非文档区域（场景布局、面板设计、散落实例、历史稿件）。
盘点时记录其存在和位置，但不纳入文档模板结构。
文档区域与非文档区域的边界在模板锁定记录中声明。
```

---

## 改进 6：跨变体一致性检查

### 现状
Task/Default 变体的图标包装与 Variant2/Variant3 不一致（Default 用原始 SVG，V2/V3 用 Bohr icon/Wrapper）。同一组件集内的变体应保持图标包装一致，但 skill 未明确要求跨变体对照。

### 建议在 icon-provenance.md 增加

```
组件集的图标审计须覆盖所有变体，不能只检查默认变体。
同一语义图标在不同变体中使用不同包装方式视为不一致，应记录并建议统一。
```
