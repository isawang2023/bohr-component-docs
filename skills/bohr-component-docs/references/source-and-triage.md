# 定位、取源与缺陷分流

在首次取源及发现未通过项时读取。局部任务只核对受影响范围。

## 定位与取源

按完整路径名在库内定位，记录 fileKey、page、nodeId、key、读取日期。库重构后旧 nodeId 全部失效，名称查找与 key 交叉核对同时做。同名多副本时人工确认权威源，不默认取第一条。

读取目标实际文字（含嵌套实例）、单体组件、组件集、属性默认值、已有中文文档和公共规范。大页分区读取，不能以截断结果代表完整检查。取源结果是后续所有环节的事实来源，写入本地证据记录；专文里每个实测数字都要能回溯到该记录。

从模块取源时继续读 [模块抽样](module-sampling.md)。

## 缺陷分流

每条未通过项都要判定归属，三选一，不允许只标“未通过”就结束：

| 归属 | 判据 | 本次动作 |
|---|---|---|
| 归属源组件 | 问题在玻尔组件库本身——图标多一层包装、用外库资产、变体组合不存在 | 不改源组件；在组件索引登记待修与修复方向，缺陷回到 Figma 侧闭环 |
| 归属文档 | 本次产物能改——说明缺失、依据分类错、场景未对齐、案例不足 | 本次改完，复验后关闭 |
| 待确认 | 源库未定义的业务语义——校验时机、权限、限额、时长、焦点 | 挂决策单交产品，不写成结论，不猜测 |

按 [权威资源定位](platform-compatibility.md#资源与产物位置) 找到组件索引，将分流结论逐条写进对应组件行。专文正文是给设计读的，索引才是跨组件汇总入口；只写在专文里，缺口无法汇总也无法排期。

## 收尾更新索引

交付时更新组件索引中该组件的来源日期、规则状态、验证缺口与分流结论。没有专文的组件族登记为“未整理”，不因本次只处理一个组件而把整族标为已接入。默认组件索引属于独立的 `bohrium-design-language` 管理范围；按平台资源目录、工作区登记或用户指定的权威位置定位维护源，不依赖两个 Skill 必须同级安装。无法定位时保留任务输出位置的待同步记录并报告缺口，不新造一个权威索引，也不直接修改安装副本。
