# 整页区域与导航验收

## 先识别用户所说的 Components

Components 可能是库内命名为 Components 的 SECTION，不等于“把普通 Frame 转成组件”，也不等于增加一章正文。先读取参考组件 page 的顶层结构与同名区域，确认用户目标；已有说明区任务不自动授权改主组件结构或新增状态。

## 全页差异清单

逐项记录参考节点、目标节点、缺口、修复与验证：

1. Components 资产区：复用库内区域类型、名称、背景绑定和组织方式。已有主组件/组件集按原 ID 归集，不克隆同名主组件，不把实例说明当作主组件已补齐。
2. 元素说明：每项写完整技术路径、职责、真实实例、实际属性类型/可选值/默认值与嵌套编辑入口。无属性写“未暴露”。普通布局 Frame 不虚构为可用组件；缺失依赖单列维护记录。
3. 状态展示：组件集各轴和默认值有标签，合法组合可定位。实例与状态文字一一对应，不能仅靠图标、颜色或图层面板才能辨认。
4. 用法文档：保留 Header / Playground / Footer / Container Line；实际实例嵌入 Auto Layout；保留版权、许可与参考链接。
5. 业务规则：保留来源、适用边界、场景、待确认项，分别记录 Web 与桌面证据。
6. 导航：逐条解析组件属性、设计文档、相关案例和跨页链接的实际目标。旧节点尚能访问也不证明内容对应；入口必须指向当前资产区或正确文档，不能继承旧组件路径。
7. 主题：参考支持 Light / Dark 时，在同一 Preview 中提供两组相同案例，读取并显式切换全部相关颜色模式；检查文本、图标、边框和内部布局背景的实际解析值。

未要求单独英文稿时，不为了机械复制参考页面而新增重复文档；保留现有英文技术标识与原稿即可。既有用户移动的位置应先读取，不能按旧坐标覆盖。

## 验收

全页区域覆盖、元素清单覆盖、真实引用、导航目标、状态标签、布局边界分别检查。结构截图只证明画布布局，不证明图标 Token、线上行为或组件发布。仍有源库缺口时准确报告，不以“文档已补齐”替代“组件已合规”。

参照按职责锁定：Button Components `296:5340` 管矩阵形式；Accordion Components `34:526` 补充完整轮廓和留白；Field 文档 `18748:157934` 管 Light / Dark 对照。规则和示例文字角色仍采用既定 Button 模板。Input `399:2794` 仅是已读取的组织证据，不作为替代模板。

## Bohrium Components 的指定形式（强制）

矩阵形式以用户指定的 Button `296:5340` 为准，结合后续指定的 Accordion `34:526` 核对外轮廓，不能用 Input 的较简结构或自制“资产区 + 说明卡片”替代。元素与属性的长说明放文档，Components 专用于可定位的资产矩阵。

- 每次先读取指定 Section、包装 Frame、Instances → Row → Instance 单元格、Labels → Label 及对应组件集。按实际值复用，不仅复制白色背景或 Section 名称。
- 2026-10-30 参照值：Section 内边距 100；矩阵行标签槽 151；上方列标签槽 25；行列 gap=0。标签 Inter Medium 12，紫色 #9747FF。单元格居中，右/下边框 1、上/左 0、INSIDE、dash=[10,5]。这些是模板标注样式，不可套给产品图标；若模板更新以现场读取为准。
- 上述边框值仅描述内部单元格；矩阵还须完整外轮廓，不得漏上/左边。Accordion 补充参照为外轮廓圆角5、Section留白80；读取当前参照后锁定适用值，不能将不同参照数字不加区分地混用。
- 按真实属性轴排列：列为 State 或 Expanded，行为 Type 或 Status。每个单元格与真实主组件/实例一一对应。尺寸适配实际组件，不压缩组件本体去凑 Button 尺寸。多子组件族允许分矩阵，完整路径作小标题，不能恢复成大段说明卡片。
- 将“实际主组件 ID 集合”与“矩阵展示 ID 集合”作差集；自动补齐遗漏变体。Boolean、文本和嵌套属性不在变体数量里，另检查是否需要实际用法对照，例如 Open=false/true 和 Disabled 的约束。不得为展示伪造业务状态或新增未授权属性。
- 保留主组件 ID、实例引用与默认变体。从源稿移动独立主组件时用其真实实例保持原稿视觉；清理仅限本次已确认空的构建容器。
- 验收行列标签、字重、颜色、边框、对齐、变体全覆盖、属性对照、引用链及正常倍率视觉。若缺失可由现有来源确定，应主动补齐，不等待用户逐项指出。

## Composer 的展示分层（优先于全量同区展示）

用户已确认 Components 主区只展示输入区基础元素。Controls、Context Select、Context Bar 和完整 Composer 归入独立 Compositions 区域；Task Step / Task Progress 归入独立对话任务进度区域。全量覆盖在相应分区内完成，不把所有组件堆进一个 Components Section。完整 Composer 的使用场景在文档中展示实例，主组件保留在业务组件收纳区。清理重复预览时保留主组件 ID、实例关系与文档案例。

Skill 与 Skill Mention 未确认可替代前保留各自入口，不按名字相似直接合并。版式参照沿用行列矩阵；同时核对矩阵外轮廓是否完整，不能只复制内部右/下分隔线而漏掉上/左边框。

## 主题对照不可遗漏

参考文档含 Light / Dark 时，必须在同一 Preview / Wrapper 下放置成对的真实实例，分别显式设置参考使用的颜色集合模式；不得只换背景。Bohrium 参考 Field 18748:157934，Light 18748:157943、Dark 18748:157956。当前涉及 Color Modes、Bohrium Semantic Colors、Semantic Colors 三套集合，实际 ID 与模式写入前读取。

核对两组案例数量、主组件 ID、属性值与尺寸一致；检查正文、边框、图标、附件及嵌套布局背景。白色基础变量不等于可随主题变化的语义变量；布局层不必要的白底应透出容器背景。发现适配缺口时修复明确属于本次组件的绑定，不覆盖文件图标多色语义或改变字体标准。源库未绑定颜色、固定渐变等缺口单列，不因有 Dark 截图就声称主题全项合规。

主题检查至少包含：默认、激活/聚焦、禁用、含附件及长内容案例中实际存在的状态；不要为了凑覆盖新增源中没有的状态。记录 Light/Dark 的 collection ID、mode ID、关键变量 ID 和各自解析色值，核对实例局部覆盖是否阻断主题继承。绑定操作若遇字体限制，按已有字体授权处理，不静默替换字体。
