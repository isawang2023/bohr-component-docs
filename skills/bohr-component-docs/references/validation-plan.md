# Skill 验证方案

## 目标与范围

验证同一模板下，简单组件、状态组件、业务组合组件的最终字段与视觉形式一致；工具受限不诱发擅自降级；再次整理可维护已有成果。

静态检查不等于行为通过。真实回归使用已授权 Figma 测试区域或副本，不改原主组件、不发布、不提交线上任务。无测试区域授权时完成输入准备与静态检查，报告真实运行待执行。图标来源用例见 [图标来源验证用例](icon-validation-cases.md)。

## 分层验证

1. 包与指令检查：运行 skill-creator 的 quick_validate，检查内部引用、UI 提示与入口一致；审查旧条款是否仍允许删栏目、各自选择模板或仅披露字体替换后交付。
2. 情境推演：逐例产出来源清单、模板选择、拟生成内容、完成状态。评估决策与产物结构，不是复述规则。只推演则明确无画布产物。
3. 真实 Figma 对照：锁定已确认模板，以同一版本整理三个代表组件，读取结构/样式并比较，检查截图、长文案重排、重复执行。
4. 异常回归：测试副本模拟缺字体、无法插入实例、线上不可用，核对写入范围与完成表述；保留恢复后按原模板完成的证据。

## 用例矩阵

| 编号 | 输入 | 必须观察到的结果 | 失败信号 |
| --- | --- | --- | --- |
| T01 | Label 等简单组件，无业务专属规则 | 信息映射齐全，不适用附理由，按参考可见结构呈现 | 自创栏目、另做便签 |
| T02 | Input，英文说明及多状态 | 英文保留，属性/默认值准确，中文使用统一模板 | 状态另造格式、改属性名 |
| T03 | Composer，无英文、多个组合 | 映射到指定模板的规则/示例结构，标新增整理，使用真实实例 | 自由展示板代替模板、仅给链接 |
| T04 | 模板字体不可用 | 保留原字体，受限项为草稿/未通过，其余继续 | 自换 Noto Sans SC 后标规范完成 |
| T05 | createInstance 成功，appendChild 失败 | 不以浮动实例叠放空卡片冒充完成；记恢复条件 | Group＋绝对定位被判为模板通过 |
| T06 | Web 不可访问、桌面仅空白窗口 | 对照字段保留，两端未验证，有据内容继续 | 虚构线上规则或删对照栏目 |
| T07 | 目标无文档，多个风格参照 | 选已确认共同模板；无确认则一个候选，不批量 | 每组件各选最近的页面 |
| T08 | 已确认模板，重复相同请求 | 不再索确认，不建重复文档，用户补充保留 | 新增“新版指南”、覆盖用户文字 |
| T09 | 说明加长至约 2–3 倍 | 自动重排，实例与后续卡片随之移动 | 只在初始长度对齐 |
| T10 | 用户明确批准模板变更 | 记录新版本/范围/迁移清单，按授权执行 | 局部例外称全库统一，或拒绝已有授权 |
| T11 | 只分析或补一条翻译 | 只读或窄范围更新，不建整页、不改其他组件 | 固定模板导致扩大任务 |

## 本轮外观偏差回归

| 编号 | 输入/注入偏差 | 必须观察到的结果 |
| --- | --- | --- |
| T12 | 用户指定 Button，技能要求覆盖五项信息 | 复用 Button 两类文档，信息映射其中，维护记录外置；不另造三板、不改用 Input |
| T13 | 标签字号相同但 Light/0.6 变成 Regular/1 | 检出并修复字重和有效透明度，不能只按字号判通过 |
| T14 | 漏 Container Line、页脚左偏 | 结构检查发现缺失，边界线适应目标页高，页脚恢复共同对齐轴 |
| T15 | 案例标题用了章节 20/32、注释提升为正文 | 恢复对应视觉角色，同倍率细节比较通过 |
| T16 | 克隆 Header 遗留 Button 文案或无关链接 | 替换授权文字和链接，保留布局、版权与许可，不伪造文档入口 |
| T17 | 示例含独立 Vector、Boolean 或复制路径图标 | 遍历发现并阻断，在本次可写中文／业务组件替换，不影响英文原稿，使用为批准库实例 |
| T18 | 示例含 HugeIcon、Material 或其他库实例 | 发现非批准库来源即失败，不能按外观放行 |
| T19 | Bohrium 图标实例或 Wrapper 内部最终实例可解析 | 记录 library/component key 与完整链路后来源项通过；其他适用验收项仍须独立通过 |
| T20 | 图标名称相同但没有库搜索和实例 key 证据 | 失败，名称不构成来源证明 |
| T21 | 库搜索无精确匹配 | 标记未找到并阻断，不猜测替换 |
| T22 | 图标存在硬编码颜色或未绑定 Paint | 清除覆盖并绑定组件库图标颜色变量，否则红线失败 |
| T23 | 图标来源正确但实际绘制的 fills/strokes 缺少变量绑定 | 仍然失败，来源和颜色变量分别验收 |
| T24 | 直接 Icon 实例或 HugeIcon 被放在业务组件中 | 替换为 `Bohr icon/Wrapper`，通过 `Bohr icon#...` 属性选库内图标 |
| T25 | Wrapper 属性指向非批准库图标或属性值无法解析 | 失败，不能以“实例存在”放行 |

T12–T25 要比较实际生成产物；推演或断言规则存在不算效果通过。先用完整的一例检查 Header、Preview、Footer、图标嵌套链路、Wrapper 属性和颜色变量绑定，再扩展数量，无需增加用户确认。

## 真实回归输入与证据

代表组件选 Label、Input、Composer，以当前可用节点为准，不把历史节点当永久有效。每次保存：
- Skill 版本/文件摘要、原请求、模板锁定记录、源节点与读取范围。
- 前后节点清单：文档、实例、mainComponent、属性、绑定、层级、尺寸。
- 模板对照表：每个文档角色的预期值/实际值/结果；比较实际输出，不只搜 Skill 文本。
- 正常与长文案截图；二次执行的文档计数和用户文字保留结果。
- 用例状态：通过、失败、未执行、受阻；证据位置、原因、影响及恢复条件。

## 放行标准

- 包检查和内部引用通过。
- T01–T03 实际产物与同一模板一致；T08、T09 维护性回归通过。
- T04–T07 受限情形未擅自改标准或虚报完成。
- T10、T11 不扩大授权范围。
- 任一关键用例未执行或受阻，只能称“修订完成，效果验证未完成/部分完成”；不以文字检查代替真实运行。

发现偏差后修复最小相关条款，重跑受影响用例及至少一个正常路径，不为每个案例堆叠互相矛盾的例外。

## 命名路径回归

| 编号 | 场景 | 验收证据 |
| --- | --- | --- |
| N01 | Composer 错挂 Input 路径、状态独立命名 | 对齐库内族名和 State 变体，旧主组件 ID 保留，实例链路可解析 |
| N02 | 相同完整路径存在多个主组件或组件集 | 查出冲突并阻断；不得借页面名或 ID 掩盖重复路径 |

| N04 | 只读盘点发现错误路径 | 输出问题，不擅自改名或合并 |

真实通过需要写入后的路径、属性和实例证据；静态条款或情境推演不等于行为验证。

## 红线回归要求

修订英文保护或图标规则时，测试题与评分标准分开保存并冻结 Skill 摘要；每题使用独立上下文，执行者只取得题目、原始材料与 Skill。必须覆盖：外库语义映射、共享主组件影响英文、原稿前后差异、无匹配与检索失败、stroke-only 及多色资产、隐藏/主题/尺寸覆盖、真实业务证据、整页缺项、重复执行和长文重排、缺字体、虚报完成、最小正常修改。首次失败不删除；静态、合成情境与真实 Figma 结果分别计数。任一适用红线失败不得以总分抵消。

## 图标引入细节专项回归

存量迁移及统计口径修订须增加I28、I29独立冷启动：受限Scale操作不能引出detach或尺寸膨胀；实例、种类、新增数必须分开，显隐检查覆盖完整祖先链。真实层以当前目标读回验证，不把历史526等数字当作固定预期。

颜色规则修订还须执行 [颜色专项 C01–C05](icon-color-workflow.md#专项用例)：语义与主题独立判定、合法 Dark 不误修、透明度不靠改色补偿。真实隔离测试保存错误注入、仅修主题、完整修复、主题切换、重复 swap 和恢复结果；分别报告已运行用例，未运行不补记通过。

修改引入检查时，按 icon-validation-cases.md 的 I20–I27 冻结专项题目与评分依据，独立冷启动测试重复缩放、颜色语义/主题、隐藏状态和正常路径。旧版结果不升级为新版通过；保留首轮失败。真实层在隔离测试页从24px主组件新建后 swap、rescale，不得只克隆正确样本冒充生成通过。检查解析描边与实际描边、父链几何、主题模式与颜色解析，再重复同一操作核对幂等性。正式源只读；保存逐节点前后快照，而非仅聚合指纹。分别报告规则决策有效、真实缺陷检出、实际修复完成与未执行范围。
