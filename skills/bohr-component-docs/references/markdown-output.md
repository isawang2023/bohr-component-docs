# Markdown 组件专文

只在任务要求 Markdown 专文时读取；Figma 画布任务不额外生成专文。

写入已确认的组件文档维护目录，推荐相对结构为 `references/components/<稳定英文名>.md`；这是产物目录，不默认指向本 Skill 安装目录。按 [权威资源定位](platform-compatibility.md#资源与产物位置) 找到并更新组件索引。专文是给 AI 读的事实与规则，不是给画布看的排版件，因此不套用画布的模板锁定、Preview 容器、Footer 对齐轴与同倍率截图要求。

专文固定六段，缺项写明原因不留空：

| 段 | 内容 |
|---|---|
| 身份、来源与状态 | 组件名与检索别名、file/page/nodeId、component key、读取日期、适用平台与主题、维护者、已知缺口 |
| 组件属性与变体 | 属性键、类型、可选值、默认值、变体轴组合；未暴露的保留一行写“未暴露” |
| 选择与组合规则 | 何时用它、何时不用、与相似组件的选择差异；共用规则只链接不复制 |
| 已有设计案例与边界 | 每条带来源、验证结论与适用边界；至少一个正常用例加一个边界用例 |
| 验证范围与待完成 | 内容、形式、场景、图标来源、图标颜色分别给通过／未通过／未验证／不适用 |
| 取源与缺口 | 取源命令与原始证据位置；未通过项的归属与恢复条件 |

专文的每个实测数字都要能回溯到取源证据记录；无法回溯的数字删掉或标未验证。

信息覆盖要求仍按 [内容字段](document-template.md#内容字段与画布映射)；只读取其中内容要求，不套用画布排版验收。
