# Figma 文件内命名规则

用于玻尔组件文档的生成、整理和已授权命名修复。目标是让中文阅读和后续代码定位使用同一组件身份。英文来自实际组件族或已批准技术标识，保持大小写；中文采用已确认术语。

## 各层名称

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| Figma 文件名 | 保留现有项目文件名；本文不授权重命名整个共享文件 | 保留实际文件名 |
| 中文组件 Page | 英文组件族 / 中文名 | Checkbox / 复选框 |
| 中文组件身份可见标题 | 英文组件族 / 中文名 | Checkbox / 复选框 |
| 规则文档根 Frame 及其可见标题 | 英文组件族 Rules / 中文名规则 | Checkbox Rules / 复选框规则 |
| 示例文档根 Frame 及其可见标题 | 英文组件族 Examples / 中文名示例 | Checkbox Examples / 复选框示例 |
| 主组件、组件集、子组件路径 | 保留库内英文技术路径，按族名和职责组织 | Checkbox；Field / Separator |
| 变体属性、变量、样式、代码标识 | 保留原技术键和值 | Checked=No；State=Default |
| 实例名称 | 对齐实际主组件/组件族，保留引用链；场景信息写在外层容器 | Checkbox |
| 业务案例容器 | 稳定场景标识 / 英文职责 / 中文职责 / 主题，平台由场景标识明确区分 | WEB-01 / Feedback / 问题与反馈 / Light |
| 普通布局和文字图层 name | 使用稳定英文职责；正文放 characters | Content Row、Actions、Title、Description、Source Note |
| 说明正文、提示及业务操作文案 | 按中文业务语境表达，不强制逐句双语 | 接受上传日志；提交 |

上述规则作用于本次中文区域；英文原稿及共享依赖保持保护。普通章节标题沿用模板术语，不要求所有正文和小标题强制添加英文。已有技术路径中的 `/` 表示层级；不要依赖拆分双语标题来推断组件技术路径。

## 定位与映射

本地命名清单逐节点记录：fileKey、page ID、node ID、节点类型、旧 name、新 name、可见标题 characters（适用时）、英文技术身份、中文显示名，以及组件/实例适用的 key、mainComponent ID/key。代码读取优先使用 ID/key 和引用关系；双语标题帮助搜索和理解，不充当唯一技术标识。

新增组件族没有英文标识时，先登记为待确认；不得把临时翻译写成既有代码接口。已有英文标识必须逐字保留，如 InputGroup 不拆写为 Input Group。实例文字覆盖不改变技术身份。

## 整理与验收

1. 先读取实际页面、文档 Frame、可见标题和目标组件族，保存旧名映射。根据任务范围仅修改中文目标；仅讨论命名规则时不批量改画布。
2. 在原节点上改名或更新标题；不删除重建，不 detach，不为标题双语化复制主组件。保留指定模板样式与层级，长标题按现有布局换行后核对重排。
3. name 与 characters 分别检查：文字图层可名为 Title，但其可见标题须含准确中英文；从 Button 模板克隆的节点不得残留按钮场景长句作为图层 name。
4. 读回页面名、文档根名、可见标题、主组件/实例链和属性；对比保护基线，并核对路径冲突。未覆盖的页面明确列出，不声称全库命名已统一。
5. 任一身份标题缺英文或中文、英文族不匹配、模板命名残留、技术标识误译或引用关系改变，命名验收未通过；仅保存规则不能算 Figma 命名整改完成。
