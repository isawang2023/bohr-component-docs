# 玻尔组件

先确定本次产物与范围，按任务读取下表细则，再取源、执行、独立读回和验收。同一组件库使用同一信息覆盖要求、已确认模板和验收口径；详细规则按下表定位，不因入口精简而省略。

首次在一个平台使用或工具/权限变化时，先读 [跨平台使用与能力核对](references/platform-compatibility.md)。`agents/openai.yaml` 仅为可选的平台展示与启动提示；核心规则不依赖它，也不依赖特定调用符号。

## 范围与保护

- 只读盘点不写画布；已有整理或修改授权直接执行，不重复询问。文档任务不自动授权改主组件属性、重命名、合并、发布组件库或线上提交。
- 英文原稿、技术标识、原组件和用户改动受保护；不得通过共享主组件、样式或变量间接修改。写前保存保护范围与依赖基线，写后核对差异，操作前读 [原稿保护](references/translation.md#英文原稿保护写入前后必检)。
- 图标必须来自批准的玻尔资产且功能对应；不以外库、占位、自绘、SVG 或 detach 替代。真实实例、主组件链、实际绘制颜色绑定、尺寸与主题分别核验；专用多色资产保留批准配色。
- 源设计、线上观察、整理建议、待确认规则分别标明。样例不自动成为业务规则；Web 与 Desktop 独立取证。
- 按任务范围复用指定模板与可编辑实例；不静默换字体、不自创展示板、不用截图替代实例。用户禁止截图时遵守，缺必要视觉证据仍记未验证。
- 每条适用红线分别判定；缺证据不放行。局部任务不扩为整页，局部通过不扩大为整组件通过。

## 按任务读取

开始时必读 [任务清单与证据记录](references/task-evidence.md) 和 [定位与缺陷分流](references/source-and-triage.md)。先区分 Figma 画布、Markdown 专文或两者，并分别列出基础中文映射、规则、状态矩阵、业务案例；已有明确约定直接复用。两种产物共用同一次取源，不重复读取。

| 本次任务 | 必须继续读取 | 执行边界 |
| --- | --- | --- |
| 局部文字、属性、图标或主题修复 | 对应下列主题细则；写入前读 [执行检查](references/execution-checks.md) | 只列受影响项；原稿保护与相关红线仍适用 |
| 中文翻译或说明修改 | [翻译](references/translation.md)；文档内容要求见 [内容字段](references/document-template.md#内容字段与画布映射) | 保留英文技术键值、版权和链接；无英文标新增整理 |
| 组织或修改 Figma 文档 | [内容与视觉模板](references/document-template.md)、[Button 模板](references/bohrium-button-template.md) | Bohrium 复用已指定 Button；其他库用其已确认模板，批量共用一个版本 |
| 整页整理、形成规范或补齐文档 | [交付约定](references/delivery-standard.md)、上一行及 [整页区域与导航](references/page-completeness.md) | 资产矩阵、属性、完整案例与导航均检查；主题按各交付根的批准范围核对，不将状态矩阵的 Light/Dark 要求套入业务规则页；新增业务案例不抵消基础缺项 |
| 创建、整理或获准修复命名 | [命名与唯一路径](references/figma-naming.md) | 读取现有族名，递归核对依赖；未读全不称全库唯一 |
| 抽取、搭建或补齐组件状态 | [组件抽取与实例验收](references/component-extraction.md)及命名规则 | 按 [能力核对](references/platform-compatibility.md#操作规范与能力映射) 加载构建操作规范；真实实例验证属性、默认值与编辑 |
| 从页面或模块抽样 | [模块抽样](references/module-sampling.md) | 区分基础、组合、模块预设与局部例外，不直接升级为公共规则 |
| 涉及图标引入、替换、缩放或主题 | [图标来源与引入检查](references/icon-provenance.md)；按其中指引读取缩放、颜色流程 | 相关变体、隐藏状态、Wrapper、实际几何与颜色均核对 |
| 涉及业务场景或组件选择 | [场景证据](references/scenario-evidence.md)、[公共依据](references/shared-rules.md) | 完整业务片段才算案例；先核对可复用原始证据，缺失时逐端实际取源，不以未尝试冒充受阻 |
| 输出 Markdown 专文 | [专文格式](references/markdown-output.md) | 六段内容覆盖，不套画布的预览容器和视觉模板要求 |
| 修改本 Skill 或验证跨组件一致性 | [维护与验证](validation/README.md) | 历史材料仅用于回归，不证明当前版本通过 |

同一任务可命中多行，合并必读文件。按需读取不等于把相关检查设为不适用；不适用必须有范围依据。

## 执行顺序

完整组件交付按 [三项内容与版式约定](references/delivery-standard.md#三项内容与版式约定) 执行：英文逐段忠实翻译、主动核对玻尔 Web/Desktop 真实业务、规则与示例分别对齐 Button。开工锁定范围，制作中保留对应关系，交付前集中对照；不另起重复验收流程。

1. **锁定任务。** 保存范围、三类参照（视觉模板、组件能力与案例、线上来源）、案例与状态映射、平台和适用检查项。无正式模板先做盘点与一个候选，确认前不批量套版。
2. **取源并分流。** 读取实际内容、属性、默认值、实例链及当前用户修改。缺陷按源组件、文档、待确认业务分流；源问题登记，授权内文档问题本次修复，未定义业务不猜测。
3. **填充内容与场景。** 映射身份来源、属性变体、基础用法、业务规则、验收缺口到模板已有位置，不强制生成五个章节。属性不存在写未暴露，证据不足写未验证；完整案例保留必要元素和关系。
4. **执行并读回。** 写入前必读 [执行检查与失败恢复](references/execution-checks.md)，先跑通一个代表单元再扩展；每个修改后的实际结果独立读取。失败保留首次证据，先查提交状态再恢复，避免重复创建或覆盖人工修改。
5. **验收并交付。** 必读 [统一验收](references/acceptance.md)，逐项比较参考与目标，修复可执行差异并复验。运行记录校验，再结合实际产物给整体状态；更新组件索引和本地进度，集中同步按工作区现行要求执行。

每步都保存产出：任务清单 → 原始取源与分流 → 内容和场景映射 → 实际产物与独立读回 → 验收结果。缺产出即该步未完成。业务案例登记 `deliverables: ["business-cases"]` 及逐场景结构，详见任务清单。

## 继续执行与完成判定

交付与检查在本 Skill 内完成，日常整理不额外调用 `component-acceptance-tracking` 再验一轮；仅在用户明确要求台账复核、历史缺口或阶段接续时使用追踪 Skill。当前流程不要求调用预算门禁。

有安全可执行缺口就继续，不能以数量达标、部分生成、列出缺口或校验器运行完作为收尾。字体或某端受阻仅挂起受影响路径，继续其他工作；恢复步骤和停止门槛见 [执行检查](references/execution-checks.md#持续执行与停止门槛)。

仅在全部适用交付与验收达成，或剩余项均确证依赖无法自主恢复的外部条件时结束。后者保留未完成状态，逐项提供失败证据、尝试路径、影响范围、恢复条件与接续节点；不无限重试、不降标准或绕过权限。

结果先给整体状态，再给结果链接、模板版本、完成范围与缺口；内容、形式、场景、图标来源、图标颜色及视觉分别判定。任一适用红线未通过或未验证，不能称整体合规。再次修改后重验受影响项，旧专项不能代替当前整体验收。整理、真实运行、发布、安装和宿主加载分别报告。

## 自带程序与外部工具

Agent 依据本 Skill 调用平台提供的外部 Figma 工具。有 `figma-use`、`figma-generate-library` 时按任务加载；其他环境按能力核对文件定位等效操作规范并实测，不能凭工具名称或文字承诺认定等效。安装 Skill 不提供连接或权限；缺能力只暂停受影响路径，区分本地草稿与远端交付。

自带程序仅校验记录，不连接 Figma、不自动审图。用法见 [程序说明](scripts/README.md)，记录要求见 [任务证据](references/task-evidence.md#收尾)。真实模板与资产留在 Figma，本次证据与进度留在工作区；历史回归材料在 `validation/`，不作为普通任务的必读内容。
